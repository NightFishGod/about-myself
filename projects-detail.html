Night🐟 数字分身系统
基于 WorkBuddy 的个人 AI 数字分身 · v4.11
创作灵感

在和 AI 助手的日常协作中，我发现一个矛盾：聊得越多，AI 忘得越快。每次新对话都是从零开始，昨天的讨论成果、上周的决策偏好、上个月的成长轨迹——全部丢失。

我信奉「边活边存」的数字自我保存哲学。既然我的工作习惯、思考方式、人格特征每天都通过对话记录下来，为什么不让 AI 持续学习这些数据，成为一个真正了解我的长期伙伴？这就是 Night🐟 数字分身的起源。

怎么做的

基于 WorkBuddy Agent 框架，设计了一套 Skill 工作流体系。核心是 night-3 自动化脚本，每日 17:30 定时触发：自动提取当天所有对话记录 → 摘要压缩 → 主题聚类 → 归因到对应话题线 → 持久化存储到长期记忆库。

最大难点是「跨天对话归因」：用户在周一和周五聊的可能是同一件事，但分散在不同会话中。我通过时间戳关联 + 关键词相似度 + 话题向量聚类，实现了跨天话题的自动合并。从 v1 到 v4.11 迭代了 4 个大版本，每次优化记忆提取精度和归因准确度。

WorkBuddy Agent 自动化脚本 长期记忆 Skill设计 Cron调度
得到了什么

现在我的 AI 助手真的「认识」我了——它知道我的工作偏好、常用工具、正在进行的项目、甚至我写代码的风格。每次开启新对话，它载入的不仅仅是系统指令，而是我过去数月的数字轨迹。

更深层的收获是工程化思维的强化：把一个抽象的「让 AI 记住我」需求，拆解成可量化的技术指标（记忆提取率、归因准确率、存储压缩比），然后用自动化脚本持续迭代优化。这种将模糊需求落地为可度量系统的能力，正是 AI 应用岗最需要的。

每日早报自动化系统
每天 8:05 自动运行 · 20+ 天零失败
创作灵感

每天早上我需要三样信息：今天天气怎么样（决定穿什么）、SSD 价格有没有波动（我在关注硬件行情）、最近有什么热点新闻。这些信息分散在不同的 App 和网站里，每天早上手动刷一遍至少花 10 分钟。

既然我是一个自动化深度用户，为什么不把这些信息整合成一份自动生成、每天准时送达的早报？这既是解决自己的刚需，也是一个展示多源数据聚合工程能力的项目。

怎么做的

设计了三模块数据流架构：天气模块调用 Amap API 获取当日天气预报和生活指数；价格监控模块多源交叉验证（ZOL / 京东 / 新浪）爬取 SSD 实时价格并标注异常波动；热搜模块抓取微博热搜 Top 10 去重排序。

所有数据清洗后以 Markdown 格式整合输出。Cron 每日 8:05 自动触发。稳定性方面做了三重保障：API 调用失败自动重试 3 次（间隔递增）、单源超时自动切换备用源、每次运行生成结构化日志便于追溯。

Amap API 多源数据聚合 Cron调度 价格监控 Markdown
得到了什么

运行 20+ 天零失败，每天早上一打开就能看到整齐的早报。最重要的是，这个项目锻炼了「多源数据聚合 + 容错设计」的工程能力——不是简单地调一个 API，而是面对真实网络中各种不稳定因素，设计出可靠的系统。

这种多源降级、异常自动恢复的设计思路，在企业的数据采集和监控系统中是标配，我通过这个项目提前积累了相关经验。

入户门 AI 效果图生产线
ComfyUI SDXL · 6 种材质 · 商业交付 50+ 张
创作灵感

在新豪轩管培生期间，我发现一个制造业的真实痛点：入户门产品效果图的出图周期太长了。传统流程是拍照 → 发设计公司 → 3D 建模渲染 → 返稿修改，一套下来 5-7 天。展会物料、销售图册常常因为等图而延误。

我刚好有一台 RTX 3060，也玩过 Stable Diffusion。为什么不把 AI 图像生成引入到传统制造业的产品展示环节？如果能用 AI 把出图周期压缩到 1 天内，对销售效率是质的提升。

怎么做的

在本地 RTX 3060 上部署 ComfyUI + SDXL 模型（Juggernaut XL / RealVisXL），搭建稳定可复用的节点工作流。为贝壳木纹、白色岩板、海石纹肌理等 6 种入户门材质建立标准化提示词模板库，覆盖不同光线和角度场景。

工作流设计为「输入产品底图 → ControlNet 控制结构 → 材质提示词渲染 → 后期精修」，一键执行。单日可产出 10+ 张商业级效果图，客户反馈后 30 分钟内可出修改稿。累计产出 50+ 张，直接用于销售图册和博览会物料。

ComfyUI SDXL 提示词工程 商业交付 Juggernaut XL LoRA
得到了什么

最直接的成果：将入户门效果图交付周期从 5-7 天压缩到 1 天内，成本从外部设计公司报价转为内部零成本。更重要的是证明了一件事——AI 不是玩具，在传统制造业中真的有商业价值。

此外，建立标准化提示词模板库的方法论，让我深刻理解了「将创意工作流程化」的重要性。不是每次从头写提示词，而是把成功案例沉淀为可复用的模板，这才是 AI 落地的正道。

个人电子简历网站
AI 协同编程 · 深色科技风 · 纯静态部署
创作灵感

2026 届应届生求职，一份 PDF 简历不够用。我想用一个在线网站来展示我的项目和能力——不是干巴巴的技能列表，而是可以互动、有视觉冲击力的作品集。

同时，我也想验证一个想法：一个不会写代码的人，借助 AI 编程工具，能在多大程度上完成一个完整的网页项目？从设计到部署，全部靠 AI 协同完成。这个网站本身就是我 AI 协同开发能力的活名片。

怎么做的

全程 AI 协同编程，使用纯 HTML/CSS/JS 单文件架构。迭代了 4 个版本：v1 基础 HTML 骨架，v2 深色科技风视觉升级（CSS 变量体系 + 渐变配色 + 玻璃态卡片），v3 动画增强（打字机效果 + 滚动渐现 + 毛玻璃导航），v4 持续补充项目内容。

部署极简：GitHub Pages 自动部署，本地编辑完 push 到 GitHub，1 分钟内上线。完全没有服务器配置、域名解析等传统部署的复杂流程。每次要补充新项目或修改描述，改一行 HTML push 一下就行。

HTML/CSS/JS AI 协同编程 GitHub Pages 响应式设计
得到了什么

一个持续迭代的在线简历站，7 个项目卡片 + 完整技能图谱 + 时间线经历。更重要的是，它证明了 AI 协同开发的可行性——我从不会写 CSS 动画，到做出打字机效果和毛玻璃导航，全程靠和 AI 对话完成。

这种「不会写代码但能交付产品」的能力，正是 AI 时代产品岗的核心竞争力。我不需要成为全栈工程师，但我知道怎么指挥 AI 做出工程师级别的作品。

听雨眠备份系统
每日双次自动备份 · 成功率 97%+ · 本地+云端
创作灵感

我的工作流越来越依赖电脑上的本地文件：ComfyUI 模型、项目代码、对话记录、工作文档……这些东西一旦丢失，损失无法估量。手动备份太容易忘，而且容易漏。

备份这件事，必须是零人工干预的自动化流程。我信奉一个原则：需要人工记住去做的系统，就是不可靠的系统。所以设计了一个完全自动化的双重备份方案。

怎么做的

四层架构设计：触发层（Cron 每日 9:00+15:00 双次调度）→ 压缩层（带时间戳 ZIP 打包，增量策略减少冗余）→ 传输层（每 3 天自动同步微云云端）→ 监控层（健康检查脚本每日验证备份完整性，异常告警）。

保留策略：本地保留最近 7 天备份，云端保留最近 4 次，防止误删同时节省空间。网络波动导致的失败自动重试，确保不丢一次备份。

自动化调度 微云备份 健康监控 容灾设计 Shell脚本
得到了什么

成功率 97%+ 的稳定运行系统，再也不用担心电脑硬盘挂了或者误删文件。更重要的收获是容灾思维的建立：任何系统都会出问题，关键不是不出问题，而是出了问题后能快速恢复。

这个项目中积累的自动化调度 + 健康监控 + 容灾恢复的设计模式，可以迁移到任何需要稳定运行的自动化系统中。

Marvis Vox · 桌面AI语音助手
VoxCPM 2 + RTX 3060 · 声音克隆 · 本地 TTS
创作灵感

我和 AI 助手的交互已经非常深入了，但始终缺少一个维度：声音。文字对话再高效，也没有语音交流的那种「人在身边」的感觉。我想让我的 AI 助手能说话——不是机械的 TTS 朗读，而是自然、有温度的中文语音。

市面上的 TTS 方案要么付费（API 按字符计费很贵），要么质量差（中文韵律奇怪），要么需要联网（我的 AI 助手是本地跑的）。我需要一个完全本地运行、中文自然、能声音克隆的方案。

怎么做的

对比了 3 种方案后选择 VoxCPM 2（中文质量高+RTX 3060 完美兼容）。搭建 CUDA 12.1 + PyTorch 2.x 环境，解决 Windows 下的依赖冲突。设计 bridge.py 文件监听架构：Marvis 输出文本 → speak.txt → VoxCPM 2 实时读取合成语音，异步非阻塞。

录制参考音频进行声音克隆——音色提取 → 模型微调，保留原声的语速和情感特征。开发了 5 套运维脚本（启动/停止/桥接/监控/配置），经历 8 轮测试覆盖文本长度边界、中英混合、特殊字符、长时间运行稳定性。

VoxCPM 2 PyTorch CUDA 声音克隆 本地TTS 文件监听架构
得到了什么

一个稳定可用的桌面级 AI 语音交互终端，我的 AI 助手现在真的能「说话」了——自然的中文语音，不是机械朗读，而是有温度的声音。

这个项目最宝贵的收获是「技术选型」能力：不是选最好的技术，而是选最适合当前约束条件的技术。VoxCPM 2 不是最强的 TTS 模型，但它是我 RTX 3060 + Windows + 本地运行约束下的最优解。这种在有限资源下做最优决策的能力，在产品岗位中至关重要。

AI 知识蒸馏工具 v2.0
Vibe Coding · YAML 评分引擎 · PyInstaller EXE
创作灵感

我经常需要看长文档——教程、技术文档、论文、会议记录。这些东西动辄几千字，但真正有用的核心知识点可能只有 20%。每次手动提炼笔记太耗时，而且容易漏掉关键信息。

我想做一个工具：把长文档丢进去，自动吐出一份结构化的知识笔记，只保留核心知识点。如果能打包成 EXE 就更好了，可以分享给同样有这个需求的同事和朋友。

怎么做的

采用 Vibe Coding 理念全程 AI 辅助开发。双入口设计：自动发现模式（扫描目录下所有文档）和手动指定模式（拖入文件或截图 OCR）。解析层支持 TXT/Markdown/PDF 文本提取 + 截图 OCR（pytesseract）。

核心创新是 YAML 配置驱动的动态评分算法——定义知识点权重、关键词匹配规则和信息密度阈值，非技术人员也能通过修改 YAML 文件调整评分策略。最后用 PyInstaller 打包为单文件 EXE，从概念到可用工具仅用 3 天。

Python PyInstaller Vibe Coding OCR识别 YAML评分算法
得到了什么

一个可用的知识萃取工具，长文档变成结构化笔记只需一键。更重要的是验证了 Vibe Coding 的效率——从想法到可用的 EXE 只用 3 天，这在传统开发流程中不可想象。

YAML 配置驱动的设计思路也让我意识到：「让非技术人员能调参数」比「写出完美算法」更重要。产品的可配置性决定了它的实用范围和生命周期。
